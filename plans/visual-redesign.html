Visual Redesign — design system + per-page rethink

2026-07-23 · feature: visual-redesign (proposed feat-012) · in-review · round 1

TL;DR

Replace the current "flat near-black + pink→gold gradient" look — which reads as a generic AI-era dark app — with a cinematic "Velvet Stage" identity: warm dark stagelight backgrounds with real depth, an editorial display serif for marquee moments, one disciplined accent, and a rethought type scale per surface (TV / phone / desktop). Every page gets a layout rethink, not just a re-skin; all existing data-testids, i18n keys, and the TV 10-foot rules are preserved.

Context

Plan 2026-07-16-karaoke-ui-overhaul (reviewed, shipped as feat-008) built the current visual layer: OKLCH tokens in app/app.css, Bricolage Grotesque + Inter, pink→gold gradient accents, TV type scale (tv-display…tv-label), tv-safe margins. feat-009 tv-beta-polish, feat-010 emoji-reactions, feat-011 guest-avatars layered on top. Last checkpoint 2026-07-18; no feature currently in-progress — clean slate for feat-012. Sean's ask: "more professional and sleek… rethink our pages, font sizes and components", explicitly inviting a Refero-driven redesign.

What the audit of current screenshots shows (ui-overhaul/screenshots 01–14, group-karaoke singking-05):

  • Landing hero headline is low-contrast grey on black; glow blob + gradient CTA is the most common AI-dark-app trope.
  • Lobby is a small card floating in a huge black void — the most-seen screen at a party has the least design.
  • Host playing view titles the song in pink→gold gradient text that fights the video content; the queue rail is a bare column.
  • Dashboard and login right-pane are mostly empty black; cards use faint pink border glows that read unfinished.
  • Gradient (pink→gold) is used for buttons, avatars, text, and icons simultaneously — the accent has no hierarchy.

The proposed identity: "Velvet Stage"

Ground truth of the subject: a living-room stage at night. The design vocabulary comes from stagecraft — spotlight falloff, velvet curtain depth, marquee lettering, a printed setlist — not from SaaS dashboards.

Palette (direction A, recommended — see Decision 1)

stage — base bg (warm wine-black)
curtain — raised surfaces
spotlight pink — THE accent (kept from brand, used alone)
brass — tiny highlights only (live dot, crown, recap)
house-lights — primary text (warm off-white)
dim — muted text

Backgrounds stop being flat: every surface sits on a radial "stagelight" gradient (warm plum falling to near-black at edges), tuned per page (bright center on lobby, dim in playing mode so video wins). The pink→gold gradient retires from controls; pink stands alone as the single interactive accent, brass appears only as punctuation. Light theme keeps the same structure as a "matinee" variant (warm paper, ink text, same pink) — tokens only, no separate layouts.

Typography

RoleNowProposed
Display / marqueeBricolage Grotesque (everywhere, bold) Fraunces (variable serif, soft+wonk axes) — hero, lobby poster, room code, "You're up", recap. Used with restraint; it IS the brand voice.
Body / UIInter (default sizing, lots of bold) Inter stays, but re-scaled: phone body 14px, labels 12px medium (not bold), tighter line-heights; weight expresses hierarchy instead of size-inflation.
Codes / datasystem mono JetBrains Mono (fontsource) for room codes, timers, counts — the room code becomes a marquee: huge, letterspaced, brass-underlined.

Signature element

The room code as theater marquee: on the TV lobby, the code renders as a poster headline in Fraunces with letterboxed spacing and a faint spotlight halo — the thing guests photograph. The same marquee treatment shrinks to the corner card while playing and to the guest phone header, so one signature travels across all three screens.

Component rules (system-wide)

  • Buttons: solid pink primary + soft ghost secondary; no gradient fills, no glow-shadow soup. One glow allowed: the primary CTA on TV.
  • Cards: 1px warm border on translucent curtain surface (subtle glass), radius stays 1rem; drop the pink border-glow.
  • Queue rows: thumbnail + title + singer chip, brass "now" marker; consistent row anatomy on TV rail and phone tab.
  • Avatars: solid curtain bg + pink initials (gradient avatars retire); photo avatars get a 1px brass ring when "now singing".
  • Motion: keep existing entrance/reaction animations; retune to slower, softer curves. prefers-reduced-motion stays wired.

Decisions needed

1. Aesthetic direction

OptionProsCons
Party-premium like Partiful; keeps pink brand equity; distinctive vs generic dark apps Warm-dark needs careful contrast tuning on TV
Smallest visual delta; safest Still lives in the most common AI-dark-app neighborhood; "sleeker" but not memorable
Most "professional" in the corporate sense Abandons pink brand; risks feeling cold for a party product

2. Display typeface (body stays Inter either way)

OptionProsCons
Theatrical, editorial, Partiful-adjacent; variable axes give one file many voices; fontsource available Serif on TV needs generous sizes (already guaranteed by tv scale)
Sharper, trendier; very light footprint Single weight/style — less range for TV vs phone
Zero migration; already variable Reads generic-modern; personality ceiling is the current problem

3. Fate of the pink→gold gradient

OptionProsCons
Single-accent discipline = the core of "sleek"; backgrounds still feel alive Loses a recognizable (if noisy) brand tick
Preserves brand tick with discipline Gradient buttons are the #1 "AI app" tell in 2026

4. Light theme investment (dark is default; rules require token-level dual-theme support)

OptionProsCons
Honors the no-hardcoded-colors rule; ~zero extra layout work; karaoke is a dark-room product Light mode is functional, not art-directed
Both themes look intentional Nearly doubles design/verification effort for a rarely-used mode

5. Scope of the page-rethink passes

OptionProsCons
All user-facing value; admin is internal and inherits new tokens for free Admin will look token-updated but not rethought
Uniform polish Significant extra effort on screens only Sean sees

Plan of record

  1. Phase 1 — tokens & type. Rewrite app.css palette (OKLCH, both themes), add Fraunces + JetBrains Mono via fontsource, rebuild type scales (TV scale keeps ≥24px floor; phone scale tightens), stagelight background utilities, retire gradient-control utilities. Acceptance: typecheck + all unit tests green; kitchen-sink page renders every primitive correctly in both themes.
  2. Phase 2 — shared components. Button variants, Card, inputs, InitialsAvatar (solid + brass now-ring), queue row anatomy, pills/chips, JoinPanel ticket, marquee code component. All existing data-testids and props preserved. Acceptance: unit tests green; kitchen-sink verified.
  3. Phase 3 — TV surfaces (/room). Lobby poster layout + playing rail layout per the per-page table. Acceptance: feature-verifier walk of host golden path at 1920×1080 with screenshots; tv-safe + ≥24px floor audited.
  4. Phase 4 — phone surface (/join). Nickname ticket, search-first layout, segmented tabs, sticky bottom bar. Acceptance: feature-verifier walk of guest golden path at 390×844 with screenshots.
  5. Phase 5 — desktop surfaces. Landing poster hero, auth split-pane with lobby vignette, dashboard green-room card. Acceptance: feature-verifier walk (landing → login → dashboard → host) with screenshots.
  6. Phase 6 — verification & ship. Full /verify-done (typecheck, 458+ unit tests, e2e smoke, build), verification doc at features/visual-redesign/verifications/, brain docs updated (design-system.md, rules/frontend.md, CHANGELOG), PR.
