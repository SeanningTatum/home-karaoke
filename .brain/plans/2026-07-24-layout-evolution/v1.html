Layout evolution — marketing landing, dashboard, party screen

2026-07-24 · feature: layout-evolution (feat-013) · draft · round 0

TL;DR

Velvet Stage (feat-012) gave us the right skin; this plan gives the pages the right bones. Three surfaces: the home page becomes a real marketing website (nav, product-shot hero, feature story, CTA band, footer), the dashboard is re-imagined as a host hub with previous sessions (real data — it already exists in D1) and a featured-playlists rail (visual placeholder for a future queue-ahead feature), and the party screen gets a spacing & rhythm pass so the TV layout stops feeling cramped and arbitrary.

Context

Checkpoint 2026-07-24: "feat-012 visual-redesign shipped + PR #12 opened" — tokens, Fraunces marquee, gradient retirement, per-page skin passes. Sean's follow-up feedback: "I like the changes that we made but we need to improve the layout all throughout the app" — home should be a legit marketing site, dashboard should anticipate previous sessions + featured playlists, party screen spacing feels off.

What the backend already has (verified today): room (code, hostUserId, status, createdAt, closedAt), roomSong (per-room played history with playedAt), song (title, thumbnailUrl). What it lacks: a "list my past rooms" query and a per-room history query — nothing lists rooms by host today. So "previous sessions" is one small repo method + one tRPC query away from being real, not fake.

Frozen constraints carry over from feat-012: all existing data-testids, i18n keys en+zh, TV 10-foot rules (≥24px text on /room, tv-safe padding), no gradient controls, brass never interactive, pink the only interactive accent.

Party screen — spacing & rhythm pass (no re-architecture)

The lobby/playing layout from feat-009/012 stays; this is a measured spacing pass. Every change below is a proposal — strike any you disagree with.

  • Adopt one TV spacing scale: 24px (gap-6) inside panels, 32px (gap-8) between panels/columns, 40px (p-10 → keep) for the hero card — replacing today's mix of gap-3/4/5/6.
  • Lobby top bar: give "Party lobby" a real band — pb-4 → pb-6, baseline-align the heading with the connection pill.
  • Lobby grid: column gap-6 → gap-8; right column roster/queue gap-5 → gap-6 so the two columns share one rhythm.
  • Roster panel: drop the fixed h-1/3 — size to content (min-h ~200px, max ~40%) so 2 guests don't float in a huge empty board while the queue starves.
  • Queue panel + roster panel: unify inner padding at p-8 (today p-6 vs p-6/lg:p-8); lobby queue items p-3 → p-4 with size-14 thumbs — 10-foot readability.
  • Playing state: remove the now-empty top bar row — move the connection pill into the right rail header, returning ~44px of height to the video.
  • Playing right rail: pl-4/pt-4 gap-4 → p-6 gap-6; QueueRail, roster strip and corner QR ticket get consistent 24px separation.
  • Now-singing banner: gap-3 → gap-4 below the title block, and give the banner a fixed two-line reserve so the video doesn't jump height between short and long titles.

FailureSurfaceBehavior

Testing plan

Risks & guardrails

  • Scope: three surfaces in one feature is the ceiling — admin, auth pages, and the phone join tabs are explicitly untouched (join phone screens got their pass in feat-012).
  • Marketing screenshots go stale: phase 3 re-captures them AFTER the phase-4 TV spacing pass, and the code comment rule from feat-012 stays ("re-capture after any TV/phone redesign").
  • TV regression: spacing changes ride the existing tv-safe/≥24px rules; the verifier walk at 1080p is the gate.
  • i18n drift: every new string lands in en+zh in the same commit — no key ships in one locale.
