## Findings for main thread

- **None app-side.** All `data-testid`s needed for this walk already existed (`room-lobby`, `room-lobby-roster-panel`, `room-roster-empty`, `room-roster-chip`, `room-lobby-queue-summary`, `room-lobby-queue-count`, `room-playing-rail`, `room-now-singing`, `room-now-up-overlay`, `join-tab-controls`, `join-controls-tab`, `room-play-pause-button`, `room-skip-button`, etc.) — no missing testid blocked this walk.
- **Environment-only observation (not a bug, no code touched):** a cold dev server needs a warm-up pass before scripted browser interaction — Vite's on-demand `optimizeDeps` discovery triggers a full client reload ("✨ optimized dependencies changed. reloading") the first time a not-yet-bundled dependency (e.g. `@radix-ui/react-alert-dialog`, `@dnd-kit/*`, `@radix-ui/react-tabs`) is imported by a route visited for the first time in that dev session. If a real user action (form fill + submit) races that reload, the in-flight submit can double as a bare HTML form GET or hit a stale React tree ("Invalid hook call" / `useMemo` on null). This is pure local-dev tooling behavior (Vite's dependency pre-bundling), not present in `bun run build`/production, and is unrelated to the `tv-beta-polish` feature — noted here only because it cost setup time and could bite the next agent running Playwright against a just-started `bun run dev`. Fix used: a throwaway warm-up pass visiting sign-up → dashboard → room → join once before the real run.
- **Hydration-race guard added to the verifier's own script (not app code):** `.fill()` immediately after `page.goto()` can commit into a `<input>` a beat before React finishes hydrating and resets the controlled value to its pre-hydration default, silently clobbering the typed text. Worked around locally in the throwaway script (`reliableFill` re-checks the committed value after a short delay) — flagging in case this is useful context for any future in-repo Playwright tooling, but this is a test-script concern, not an app defect.
