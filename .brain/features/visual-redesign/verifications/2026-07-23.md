## Scope note — derived step

The task's golden path assumed adding a song to the queue would surface the TV "now playing" state directly. Reading `app/lib/room-state.ts` (`applyClientMessage`) showed `queue.add` never auto-advances playback — `playback.play` is a separate, host-gated message sent from the "Start Party" button in the phone Controls tab (`app/components/join/controls-tab.tsx`). That tab only renders when `isHost` is true (session id === room's `hostUserId`), so to reach the TV playing state for real I added **step 09b**: the host opens their own `/join/:code` (in the same authenticated browser context, own "phone"), fills the (always-shown) nickname gate, taps the Controls tab, and taps "Start Party". This is real product behavior, not a scripting shortcut around a bug — confirmed by reading the pure state-transition code before assuming a redesign regression.

## Visual QA notes (styling-specific, beyond functional pass/fail)

- **Serif marquee**: confirmed on login vignette (`KQ7-3FP`), room lobby hero (`7Y3-AJC`), both using the Fraunces `tv-code` utility over a brass-colored underline rule — matches "marquee room-code signature" spec.
- **Warm wine-black bg, not flat black**: confirmed via `app/app.css` `.dark` tokens (`--background: oklch(0.168 0.028 348)` ≈ `#1a0a13` wine-black, not `#000`) and visually in every screenshot — there is a visible warm radial stagelight glow (`bg-stagelight` / `bg-stagelight-dim` utilities), not a flat black fill.
- **Single pink accent, no pink→gold gradient on primary CTAs**: grepped `app/` for `gradient` — the only hits are: (a) the two sanctioned ambient `bg-stagelight(-dim)` radial glows in `app.css` (explicitly commented "the ONLY sanctioned gradient use... pink→gold retired from controls & text"), (b) a bottom scrim gradient on the join page bottom bar (`bg-gradient-to-t from-background...`, a fade mask, not a color-hue gradient), (c) admin dashboard stat cards (out of scope — admin inherits tokens only per feature doc), and (d) two explicitly-commented "sanctioned" exceptions: the search-tab "add song" `+` button and the TV host play/pause control, both called out in code comments as "one of the three places the gradient accent is deliberately used" per `design.md §3`. All primary CTAs verified in screenshots (landing "Join the party", login "Sign in", dashboard "Host a karaoke room") render as solid pink, not gradient-filled.
- **TV now-playing title is cream, not gradient text**: read `app/components/room/now-singing-banner.tsx` — the `isTv` branch renders `className="tv-title text-foreground line-clamp-2 break-words"` (plain solid-color text), confirmed visually in `10-tv-now-playing.png`. A stale doc-comment on the component's props (line 8-9) still says "tv-headline size + gradient accent text" — this is outdated prose, not reflected in the actual JSX; flagged below as a doc-hygiene finding, not a styling defect.
- **Brass punctuation**: confirmed on the room-code marquee underline rule (login vignette, room lobby) and the TV "sung by {name}" credit line (`text-brass` class) — both a warm gold/brass hue distinct from the pink accent.
- **Minor content nit (pre-existing, not a redesign regression)**: on the phone Queue tab after adding the first song (`09-phone-added.png`), the "Queue is empty — scan to add songs" idle banner text (`room.banner.idle` i18n key) still renders above the populated queue list. This is the `NowSingingBanner`'s "nothing is currently playing" idle state (i.e. "queue" here means "now playing," not "the list below"), which is existing copy/behavior unrelated to this visual-redesign feature — not a regression introduced by this task, but worth a copy clarification pass (e.g. "Nothing playing yet") for a future task.

## Findings for main thread

1. **Doc-comment drift** (very minor): `app/components/room/now-singing-banner.tsx` lines 8-9 describe the `tv` size variant as having "gradient accent text," but the actual JSX renders plain `text-foreground` (solid cream) — matches the intended Velvet Stage decision (gradient text retired). The comment should be updated to avoid confusing a future reader into thinking gradient text is expected/missing.
2. **Pre-existing copy ambiguity** (not a redesign regression): the phone Queue tab's idle "Queue is empty — scan to add songs" banner (`room.banner.idle`) stays visible even when the queue list below it has items, because it actually describes "nothing playing right now," not "the queue is literally empty." Confusing wording, out of scope for this visual pass.
3. No missing `data-testid`s were hit — every element needed for the golden + error path had one (`login-email`, `login-password`, `login-submit`, `dashboard-host-room-button`, `room-code-text`/marquee code, `join-nickname-input`, `join-nickname-submit`, `join-search-input`, `join-search-submit`, `join-search-add`, `join-tab-controls`, `controls-start-party`, `room-playing-rail`, `room-unavailable`).
